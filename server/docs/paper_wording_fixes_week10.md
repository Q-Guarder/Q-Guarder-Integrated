수치·표는 고칠 필요가 없습니다(표 6·7, 3.4절 수치 모두 서버 융합 함수로 재현됨).

## 1. 3.4절 — 상황 B 모사 실험 문구 (수정 필요)

**현재**

> VT의 유효 판정 엔진 수와 정보 가용 상태를 유지하고 악성 탐지 엔진 수를 0으로 설정한 결과, 경로 포함 피싱 URL 84건 중 26건(31.0%)이 탐지되었다.

**문제**

84건 중 7건은 실제로 VT 미등재(상황 C)입니다. "정보 가용 상태를 유지"하면 이 7건은 상황 C로 남아
ML 가중치 0.80이 적용되므로 결과가 달라집니다.

| 계산 방식 | 결과 |
|---|---|
| 84건 전부를 "VT 정보 유효, d=0"(상황 B)으로 가정 | **26/84 (31.0%)** ← 논문 수치 |
| 정보 가용 상태 유지 (등재 77건만 B, 미등재 7건은 C) | 29/84 (34.5%) |
| VT 등재 77건만 대상으로 d=0 설정 | 25/77 (32.5%) |

**수정안 A (권장 — 수치 유지, 문구만 변경)**

> 독립 테스트 데이터의 경로 포함 피싱 URL 84건 전체를 VT 정보는 유효하나 악성 탐지 엔진이 없는 상태(d=0)로 가정한 결과, 26건(31.0%)이 탐지되었다.

**수정안 B (문구 유지에 가깝게, 수치 변경)**

> VT에 등재된 경로 포함 피싱 URL 77건의 유효 판정 엔진 수를 유지하고 악성 탐지 엔진 수를 0으로 설정한 결과, 25건(32.5%)이 탐지되었다.

참고: 상황 B·경로 포함 URL은 `S_final = 0.50 × P_ML`이고 τL = 0.45이므로, 탐지 조건은 `P_ML ≥ 0.90`입니다.
84건 중 `P_ML ≥ 0.90`인 URL이 26건입니다.

## 2. 2.3절 — d, n의 정의 (보완 권장)

**현재**

> VT의 악성 탐지 엔진 수 d, 유효 판정 엔진 수 n 및 정보 가용 상태를 기준으로 …

**실제 계산** (`app/services/hybrid_engine.py`의 `scan_url_with_virustotal`)

- d = VT `last_analysis_stats`의 `malicious` + `suspicious`
- n = `last_analysis_stats` 전체 합 (`harmless` + `undetected` + `malicious` + `suspicious` + `timeout`)

즉 d에는 "의심(suspicious)" 판정이 포함되고, n에는 시간 초과(timeout) 엔진도 포함됩니다.

**수정안 (정의 문장 한 줄 추가)**

> 여기서 d는 VT 분석 통계에서 악성(malicious) 또는 의심(suspicious)으로 판정한 엔진 수의 합이며, n은 분석 통계에 포함된 전체 엔진 수이다.

이 문장을 넣으면 본문의 "악성 탐지 엔진 수", "유효 판정 엔진 수" 표현은 그대로 두어도 됩니다.
("유효 판정 엔진 수"를 "전체 분석 엔진 수"로 바꾸면 더 정확합니다 — 2.3절 2곳, 3.4절 1곳.)

**코드를 논문에 맞추는 방법은 권장하지 않습니다.** d를 malicious만으로 바꾸면 상황 분류가 달라져
표 6~8을 전부 다시 계산해야 합니다.
